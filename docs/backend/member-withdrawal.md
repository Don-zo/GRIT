# 회원 탈퇴

`DELETE /api/members/me`에 본인의 `Authorization: Bearer <access token>`을 전달한다. 요청 본문은 없다. 성공하면 `204 No Content`와 `refresh_token` 만료 쿠키를 반환한다. 클라이언트는 성공 응답 후 저장된 access token을 지우고 로그인 화면으로 이동한다.

## 삭제 정책

- 회원, 모든 refresh token, 할 일, 카테고리, 주간 공부 시간, 타이머 상태를 실제 삭제한다.
- 본인이 추가한 친구 관계와 상대방이 추가한 친구 관계를 모두 제거한다.
- 가입한 그룹에서 탈퇴하고 실제 가입자 수로 인원을 갱신한다. 다른 회원이 있는 그룹과 그 뽀모도로는 유지한다. 마지막 회원이 탈퇴하면 그룹과 뽀모도로를 함께 삭제한다.
- 탈퇴한 회원 ID의 기존 백엔드 access token은 만료 전이어도 인증 필터에서 401로 거절한다. 모든 refresh token도 재발급에 사용할 수 없다.
- 같은 구글 계정으로 다시 로그인하면 새로운 ID의 `PENDING` 회원으로 생성된다. 이전 데이터는 복구하지 않는다. 이메일과 닉네임을 다시 사용할 수 있다.
- 현재 프로필 이미지 삭제 작업을 DB에 저장한다. 다른 회원이 사용하는 이미지는 보존한다. 작업 완료 후에는 작업 행도 삭제한다.

## 응답과 외부 리소스

탈퇴 요청은 DB 삭제와 이미지 정리 작업 저장을 하나의 트랜잭션으로 커밋한다. 요청 처리 중 S3 또는 LiveKit API를 호출하지 않는다. 응답 시간은 DB 상태와 개인 데이터 양에 영향을 받으며, 외부 리소스 정리 완료를 기다리지 않는다.

별도의 스케줄러가 이미지 작업을 기본 5초 간격으로 확인한다. 작업당 트랜잭션을 분리하고 PostgreSQL `FOR UPDATE SKIP LOCKED`로 여러 인스턴스가 같은 작업을 동시에 처리하지 않도록 한다. 실패하면 5초부터 최대 1시간까지 지수 backoff로 계속 재시도한다. 재시도 횟수와 다음 시각을 DB에 저장하므로 프로세스가 재시작되어도 작업이 남는다. S3 삭제 후 DB 커밋에 실패해도 재시도가 가능하다. S3의 없는 객체 삭제는 정상 처리된다.

사용자가 선택한 정책에 따라 **LiveKit은 기존 토큰 자연 만료에 맡긴다.** 연결 종료 API, TTL 변경, 참가자 식별자 변경은 포함하지 않는다. 백엔드 토큰 차단은 LiveKit 토큰을 철회하지 않는다. 기존 LiveKit 연결은 계속 유지될 수 있고 토큰이 유효한 동안 직접 재접속할 수도 있다. LiveKit은 연결 중 토큰을 갱신하므로 토큰 만료 자체가 접속 종료를 보장하지 않는다. 이는 이번 탈퇴 정책의 명시적인 범위다.

## 배포

자동 migration 도구는 현재 프로젝트에 없다. `src/main/resources/db/migrations/20261026_withdrawal_cleanup.sql`을 운영 PostgreSQL에 먼저 적용한 후 배포한다. 운영 설정의 `ddl-auto=update`도 테이블을 생성할 수 있지만 배포 전 명시적 적용을 권장한다. 기존 데이터를 변경하는 DML이나 전체 soft delete 전환은 없다.

운영에서는 아래 쿼리로 실패한 작업 수와 가장 오래된 작업을 확인할 수 있다. 실패 로그에는 작업 ID와 재시도 횟수만 남긴다.

```sql
SELECT count(*), min(created_at), max(attempts)
FROM withdrawal_cleanup;
```

## 검증

```sh
cd backend/grit
./gradlew test --tests 'grit.domain.*'
```

탈퇴 통합 테스트는 H2의 실제 외래 키와 Spring 트랜잭션을 사용한다. 개인 데이터와 친구 관계 삭제, 다른 회원 데이터 보존, 빈 그룹·뽀모도로 삭제, 기존 refresh token 차단, 신규 재가입, 미초기화 회원 탈퇴를 확인한다. 외부 호출 없는 탈퇴 응답, 작업 저장의 원자성, S3 실패 후 영속 재시도, 공유 이미지 보존도 확인한다. API 테스트는 실제 서명된 JWT로 204·만료 쿠키 및 탈퇴 회원의 401을 확인한다. S3는 mock이며 실제 외부 객체를 삭제하지 않는다. H2 테스트는 운영 PostgreSQL의 다중 워커 동시 실행을 실증하지 않는다.
